# Standby

把「开赛前的支持」变成一条**改不了、查得到**的记录，赛后可以清算；再按**这场比赛所属游戏**的成分给发言定权重。

针对的是「串子」：比赛没开打之前不表态，等结果出来再补一条评论说自己站过某一边。

**线上：<https://wialcjvurrs2n.space.mcode.cn>**

---

## 三个不变量

1. **赛前锁定。** 开赛前签一条「我支持 X」，签名连同一个别人改不了的时间锚写进账本。改一个字签名就对不上。
2. **不能倒填。** 判定「是否赛前」用的是**时间锚**，不是粉丝自己填的时间。倒填会被拆穿。
3. **权重不串游戏。** 英雄联盟比赛只看这个人的英雄联盟段位。王者荣耀的段位会列在档案里，但不抬高他在这场比赛里的分量。

## 跑起来

```bash
npm run build     # 构建到 dist/，跑完六道闸门
npm run serve     # http://localhost:8899
npm test          # 70 个测试
npm run publish   # 把 inbox/ 里的社区投稿并进公开账本
```

**没有运行时依赖，也不需要 `npm install`，也没有打包器。**
浏览器直接加载 `core/` 里的 ES 模块，所以发布出去的和测试覆盖过的是同一份代码。

## 它怎么工作

每个人在自己设备上有一把长期 Ed25519 密钥，私钥用口令加密后从不离开本机。
开赛前用它签一条站队，连同一个时间锚追加写进哈希链。之后在任何平台评论，末尾贴一行：

```text
赛前 T1 · 英雄联盟 璀璨钻石 · 认证 https://…/p/0x714eacef…7fb2
```

**前面几个字是给人看的。** 改成「最强王者」也没有用——核对页只认签名里的内容。
复制别人的链接也不行：页面上会显示那把指纹绑定的是哪个账号。

### 发言权重

公开、固定、可审计，**只由本场所属游戏的开赛前段位决定**：

| 权重 | 规则 |
|---|---|
| 高 | 大师及以上 |
| 中 | 翡翠 — 钻石 |
| 低 | 铂金及以下 |
| 未认证 | 该游戏没有开赛前已锚定的快照 |

段位按**段位表位置**比较，不按字典序——「钻石」一定排在「黄金」前面。
快照是**追加写**的：讨论某场比赛时取开赛前最近的那一份，所以赛后才爬上宗师也不改写本场的「低」。

### 段位来源

每条快照都带来源标记，页面上原样显示，不混为一谈：
**官方接口** / **他人背书** / **自报**。

厂商密钥不能进静态网页，所以官方段位需要部署方另外提供一个只做查询的代理
（参考实现在 [`proxy/`](proxy/README.md)）。**没配代理时本站不会假装能拉到官方数据**，
只会退回自报并如实标注。王者荣耀没有公开接口，任何配置下都只能自报。

## 怎么用真实赛程

随站点发布的是**示例赛程**（首页有明确标注）。真实赛程有三种接法：

1. **站内导入** — 打开「导入赛程」，粘贴 CSV 或 JSON。边输入边校验，有一行不对就整批拒绝。
   每场比赛会写进哈希链，开赛时间之后改不动。
2. **维护方发布** — 把用户导出的账本包放进 `inbox/`，执行 `npm run publish`。
   脚本逐个验证签名与链，分叉的包被拒绝而不是被「挑一边」。
3. **远程账本** — 在「设置」里把账本地址指向自己托管的 JSON，
   公开账本就能持续增长而不必重新发布整站。也可以用 `?ledger=<地址>` 临时指定。

```csv
matchId,gameId,teams,kickoffAt
lck-2026-s11-w1,league-of-legends,"T1,BLG",2026-11-01T12:00:00Z
lck-2026-s11-w2,league-of-legends,GEN,JDG,2026-11-02T12:00:00Z
```

队伍列加不加引号都可以。

## 信任边界

- **挡不住一人多号。** 签名只证明「这把钥匙签过」，不证明背后是一个真人。买号、代打、多开都挡不住。
- **挡不住借号。** 靠周期性重新授权让借号失效。
- **默认时间锚挡不住改表。** 设备时钟用户可以自己改。接入服务端时间锚或 OpenTimestamps（比特币区块背书）之后这一条才真正站得住。页面会明示当前用的是哪种。
- **挡不住运营者。** 但账本公开、链可复算：改一条后面全断，**断裂位置会直接显示在页面上**。收据页在链断裂时不显示「找不到」，而是显示「账本校验失败」——校验不过的链，任何结论都没有意义。

## 自己验一遍

每一条结论都可以离线复算，不需要相信这个网站：

1. 下载 `web/data/ledger.json`，它是一条哈希链
2. 改动其中任何一条记录
3. 重新构建并打开同一张收据页
4. 站点会拒绝给出任何判定，并告诉你链断在第几条

## 六道构建闸门

| 闸门 | 拦住什么 |
|---|---|
| 账本校验 | 哈希链断裂，或有记录签名不过 → 不出包 |
| 导入解析 | 相对导入或字体路径解析不到 → 不出包 |
| 路由绑定 | 路由引用了没导入的视图 → 不出包 |
| 编码 | 出现 U+FFFD 乱码 → 不出包 |
| 语法 | 按 **ESM** 解析失败 → 不出包 |
| 输出复核 | 写盘前重新验证产物本身 |

> 语法闸必须按 ESM 解析。`node --check foo.js` 在 `package.json` 没有
> `type: module` 时会走另一条解析路径，真的放过过浏览器会拒绝的错误。

## 结构

```
core/            同构核心：浏览器和测试跑的是同一份代码
  canonical.js     规范化 JSON + 摘要
  keys.js          Ed25519 长期密钥，域分隔签名，公钥/指纹编解码
  ledger.js        追加写哈希链，含合并与分叉拒绝
  anchor.js        时间锚：本地 / 服务端 / OpenTimestamps / 固定时钟
  rank.js          段位阶梯、权重分档、峰值追踪
  rank-source.js   官方接口与自报的来源区分
  schedule.js      赛程解析（CSV / JSON），整批校验
  protocol.js      绑定、快照、承诺、核对（核心）
  vault.js         口令加密的密钥库
  bundle.js        账本包的导出、校验、合并
web/             静态站点
  index.html       单页外壳
  js/app.js        路由与启动
  js/store.js      本机状态、密钥库、账本装载
  js/actions.js    所有写操作的唯一入口
  js/ui.js         DOM 构建工具 + 确定性战队徽章
  js/views/        公开页与账号页
  data/ledger.json 随站点发布的公开账本
  fonts/, img/     自托管字体与主视觉
tools/
  build.mjs               构建 + 六道闸门
  make-public-ledger.mjs  生成示例账本（时间相对构建时刻）
  publish.mjs             合并 inbox/ 里的社区投稿并发布
proxy/           官方段位代理（Cloudflare Worker 参考实现）
test/            70 个测试
```
